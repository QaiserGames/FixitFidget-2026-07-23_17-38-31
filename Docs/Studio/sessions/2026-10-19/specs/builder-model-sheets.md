## Why it exists
His girlfriend's playtest (19 Oct) found Grace's camera strap see-through in the game: its leather faces point the wrong way, so Unity (which draws front faces only) culls them, while its stitches and edges (separate meshes) float in the air. It looked right in the Blender review renders because Blender draws both sides. Every check passed ("All good") because they checked presence and size, never what a player would actually SEE. He asked for "something that reviews EVERYTHING AND EVERYTHING, because these silly mistakes I want to get ahead of". This tool is the model half of that review: it renders every model the way Unity draws it, from every side, and measures each part automatically.

## Files you write (complete files)
1. `/root/code/Assets/Editor/ReviewModelSheets.cs` — wrapped in `#if UNITY_EDITOR … #endif` like every editor script here.
2. `/root/code/Assets/Editor/Review/ReviewFace.shader` — `Shader "Hidden/FixitFidget/ReviewFace"`: unlit, `ZWrite On`, `ZTest LEqual`, `Cull [_Cull]` (enum property `[Enum(UnityEngine.Rendering.CullMode)] _Cull ("Cull", Float) = 0`), properties `_Front ("Front", Color) = (1,1,1,1)` and `_Back ("Back", Color) = (1,0,0,1)`; fragment returns `_Front` for front faces and `_Back` for back faces using `SV_IsFrontFace` (bool or `FRONT_FACE_TYPE`/`IS_FRONT_VFACE` — make it compile on Metal (his Mac) and D3D (his PC)); a plain `CGPROGRAM` or `HLSLPROGRAM` pass with NO LightMode tag (URP draws untagged passes as SRPDefaultUnlit) and `#include "UnityCG.cginc"` is fine. Keep it tiny and robust.

## For each subject
1. Place it; put its lowest point on y = 0 at the origin. Gather its parts: every `Renderer` (MeshRenderer with a MeshFilter, SkinnedMeshRenderer) in the instance, INCLUDING inactive GameObjects and disabled renderers. Record for each part: hierarchy path, active-in-prefab, renderer enabled, mesh name, triangle count, world bounds size (mm), lossyScale (mirrored if an odd number of negative axes), materials (name, shader name), shadowCastingMode.
2. **Sheet** (real materials, as authored: only the parts that are active and enabled): 8 views — the four sides (+X, −X, +Z, −Z), top (looking down), bottom (looking up), and two three-quarter views from above (+X+Y+Z and −X+Y−Z). Perspective, FOV 30°, distance so the subject's bounding sphere fits with ~12 % margin, 640 × 480 each; composite into one 4 × 2 PNG (2560 × 960) with 4 px dark separators. Save `<subject>-sheet.png`.
3. **X-ray sheet**: the same 8 views with every part (active and enabled) drawn in its own flat colour (the ReviewFace shader with `_Cull = Back` and `_Front = _Back = its colour` — Cull Back is what the game does, so an inside-out part shows as missing here), distinct hues (golden-ratio hue steps, saturation .65, value .95); background near-black. Save `<subject>-xray.png`; list part → colour (hex) in the report.
4. **The face test (the heart of it)** — for EVERY part (active or not, enabled or not; temporarily activate/enable it, and keep the rest as authored so they occlude as in the game), from 14 directions (6 axes + 8 cube corners): draw the target part with ReviewFace (`_Cull = Off`, front white, back red) and every OTHER visible part with an occluder material (ReviewFace, `_Cull = Back`, both colours black) — so the target's own pixels are counted only where a player could see them. Frame the TARGET: camera on the line from the target's bounds centre, outside the whole subject (distance = subject radius × 2.2 + target radius), FOV to fit the target's bounding sphere × 1.15 (clamp 1.5°–60°), 160 × 160, near/far set from the distances. Count white (front) and red (back) pixels (threshold, anti-aliasing tolerant: red = r > .5 && g < .35; white = r > .5 && g > .5; ignore the rest). For each direction with ≥ 30 counted pixels, back share = red / (white + red).
   - Flag **SEE-THROUGH** when any direction's back share ≥ .25: "from <direction>: <n>% of what you'd see of it is the back of its faces — the game draws front faces only, so from that side it's see-through/invisible". Severity S1 if any direction ≥ .5, else S2. List all directions over .25 with their shares.
   - Flag **NEVER SEEN** (S3, info) when every direction has < 30 counted pixels (fully hidden by other parts, or too small) — useful for the purpose rule ("every part has to mean something").
   - Save, for each flagged part, `flag-<subject>-<part>.png`: the worst direction rendered twice side by side (left: the subject in real materials from that direction, framed on the target; right: the face render), 2 × 320 × 320.
5. **Material checks** per part: a null material slot (S1); fewer materials than submeshes (S2); shader missing/unsupported/error shader (`!shader.isSupported` or name contains "InternalErrorShader") (S1); URP Lit-family transparent surface (`_Surface` == 1) with base colour alpha < .98 (S2: "see-through material"); alpha clipping on with `_Cutoff` > .5 (S3); `_Cull` (Render Face) == 0/Both (info) or == Front (S2).
6. **Renderer checks**: `ShadowCastingMode.ShadowsOnly` on a part that would be seen (S2); mirrored scale (info: "mirrored — Unity flips its faces back for you, Blender exports may not"); mesh null or 0 triangles (S1); bounds under 0.2 mm (S3).

## Hard rules for this codebase (read carefully)
- Unity 6.5: `Object.GetInstanceID()` no longer compiles — never use it (use `GetEntityId()` or names/paths). Use `Object.FindObjectsByType<T>(FindObjectsInactive.Include, FindObjectsSortMode.None)` (not the old FindObjectsOfType).
- Comments explain WHY, in plain words, and quote his note where a change answers one (look at the header comments in HeroDeviceSteps.cs and BenchScaleAudit.cs for the voice). A header comment block at the top explains what the tool does and why (the strap story).
- Never write to the open scene, prefabs, or assets. Destroy every material/texture you create (`Object.DestroyImmediate`) — `Studio.Dispose` only cleans what it made.
- Mesh access: in the editor, reading `sharedMesh` vertices/triangles of an imported mesh may be blocked if not readable; you don't need vertex access for this design (renders only) — keep it that way; triangle counts via `mesh.GetIndexCount(sub) / 3` per submesh (works without read access) or `mesh.triangles` only if `isReadable`.
- `PreviewRenderUtility` + URP: `Studio.Shoot` already renders twice (warm-up); keep that pattern. If you need a different background colour for the face test (black), set `Utility.camera.backgroundColor` before shooting and restore it.
- Must compile with no warnings-as-errors issues: no unused variables that trip analyzers, no ambiguous `Object` (use `using Object = UnityEngine.Object;` as other files do).
