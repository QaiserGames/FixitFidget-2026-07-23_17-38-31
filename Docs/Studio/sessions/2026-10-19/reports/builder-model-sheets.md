## Built (two new files, nothing else touched)

1. `/root/code/Assets/Editor/ReviewModelSheets.cs` (1154 lines, `#if UNITY_EDITOR`, `internal static class ReviewModelSheets`). Four menu items under `Fixit Fidget/Review/` (same style as the sibling `Review/Screens 1-2` tool). Per subject, in a `BenchScale.Studio` preview scene (one Studio per subject, as the project's other photo steps do; placed instances go with its scene, never destroyed twice):
   - gathers every MeshRenderer+MeshFilter / SkinnedMeshRenderer (active or not, enabled or not); texts (TMP), UI (RectTransform), the job tag (JobMarker subtree), sprites/lines/trails/particles are listed as "skipped"; Cameras, AudioListeners and Canvases on the instance are switched off (a world-space Canvas would otherwise leak white into the face test); LODGroups are forced to LOD 0 and LOD≥1-only renderers are marked "not drawn at LOD 0, not tested".
   - lowest drawn point on y=0, middle on the origin (translate only, rotation kept); bounds from each mesh's box through its transform (works for switched-off renderers).
   - material checks (empty slot S1, fewer materials than submeshes S2, broken/unsupported/InternalError shader S1, URP `_Surface==1` with base alpha <.98 S2, alpha clip with `_Cutoff`>.5 S3, `_Cull` 0/Both S3 info, `_Cull` 1 (= Render Face "Back", i.e. CullMode.Front) S2); renderer checks (ShadowsOnly on a drawn part S2, mirrored via `localToWorldMatrix.determinant < 0` S3 with the "Unity flips its faces back for you, Blender exports may not" wording, null mesh / 0 triangles S1, <0.2 mm S3). Triangles via `GetIndexCount/GetTopology` (no read access needed).
   - the face test exactly as specified: per part, 14 directions, target in ReviewFace Cull Off white/red, every other authored-visible part in ReviewFace Cull Back black, black background, camera at subject radius×2.2 + target radius on the line from the target's centre, FOV to fit target sphere×1.15 clamped 1.5–60°, 160×160, near/far from the distances; pixel thresholds as given (counts normalised to 160² when the preview comes back at Retina scale); ≥30 px per direction; SEE-THROUGH S1 (≥.5) / S2 (≥.25) with every direction over .25 listed; NEVER SEEN S3. Two refinements, both explained in comments: a part whose materials ALL have `_Cull==0` (Render Face Both) gets S3 "BACK FACES, DRAWN BOTH SIDES" instead of SEE-THROUGH (the game shows it); a part whose materials are ALL URP Transparent is "clear": it does not occlude in the test and is left out of the x-ray (otherwise the watch's spring under its glass reads NEVER SEEN).
   - the 8-view real sheet (4×2 of 640×480 → 2560×960, 4 px separators drawn over the cell edges, each view labelled with a built-in 5×7 pixel font) and the x-ray sheet (golden-ratio hues, S .65 V .95, Cull Back, near-black background, legend part→#hex in the report).
   - `flag-<subject>-<part>.png` (real view | face view from the worst direction, 2×320×320 plus a 4 px separator, labelled) for every part with a SEE-THROUGH / NEVER SEEN / both-sides flag or any S1/S2 flag.
   - Output `Logs/Review/models-<yyyy-MM-dd_HHmmss>/`: sheets, flag pictures, `report.txt` (header: menu, time, Unity version, subjects/parts/flags by severity, cancelled/error notes, a "how to read" paragraph; FLAGS FIRST sorted S1→S3, each line severity | subject | part path | kind | detail | from | image; then per subject its notes, a parts table (path, tris, size mm, worst back share + direction, active/on, materials (shader)) and the x-ray legend), `flags.json` (array of {severity, subject, part, kind, detail, from, directions:[{dir, backShare, pixels}], image}). Console: `[Review] Model sheets N: <n> subjects, <m> parts, <k> flagged (S1 a, S2 b, S3 c). Logs/Review/models-…` (LogWarning if any S1, LogError if the run stopped on an exception). Invariant culture throughout (`Inv(FormattableString)` helper, same pattern as ReviewScreenGather).
   - Progress: `EditorUtility.DisplayCancelableProgressBar` per subject and per part; `ClearProgressBar` in `finally`; cancel throws `OperationCanceledException`, caught at the run level, and the report/json/console line are still written with what was done. All four refuse Play mode (LogError + return, plus greyed validators). No SaveAssets, no importer changes, no prefab writes, no MarkSceneDirty, no Undo. Every material/texture I make is destroyed (face materials in `Face.Dispose`, x-ray materials per subject, every shot texture after reading, the composite textures in `Picture.Save`).
   - Model sheets 4 grouping: walk each loaded scene's roots; an outermost prefab instance root is one group (deduplicated by prefab asset path, one instance tested); plain objects group with their plain descendants, stopping at nested prefab roots (which become their own groups); a group over 400 renderers is split: the object's own renderers as a small group, then each direct child gathered recursively (split prefab groups are deduped by "prefabPath/childName"). The group is copied with `Object.Instantiate(original, new InstantiateParameters { scene = preview, worldSpace = true })` straight into the preview scene (inside `#if UNITY_6000_0_OR_NEWER`, with a try/catch fallback to `Instantiate` + `MoveGameObjectToScene`), given the original's world pose and lossyScale, its MonoBehaviours switched off; renderers belonging to other groups inside the copy are hidden for the face test (shown as authored on the real sheet). No sheets for scene groups unless the group has a flag, then both sheets.

2. `/root/code/Assets/Editor/Review/ReviewFace.shader` — `Shader "Hidden/FixitFidget/ReviewFace"`: properties `_Cull` (`[Enum(UnityEngine.Rendering.CullMode)]`, Float, default 0), `_Front` (1,1,1,1), `_Back` (1,0,0,1); one untagged CGPROGRAM pass (`Cull [_Cull]`, ZWrite On, ZTest LEqual, Blend Off, UnityCG.cginc, `FRONT_FACE_TYPE face : FRONT_FACE_SEMANTIC` + `IS_FRONT_VFACE` with an `#ifndef` fallback to bool/SV_IsFrontFace) and, as insurance, a `LightMode = DepthOnly` pass with the same culling (so the shader survives URP depth priming if it is ever switched on). `#pragma target 3.5` because SV_IsFrontFace needs a shader-model-4 profile on D3D11. Fallback Off.

## Known limits
- Occlusion in the face test is by the subject's own solid parts only: other groups' renderers (scene mode), sprites/particles/text and anything outside the subject don't occlude; transparent (URP `_Surface==1`) parts never occlude, opaque parts always do even if their texture has holes (alpha clip).
- Only LOD 0 is reviewed; SkinnedMeshRenderer bounds use the mesh's bind-pose bounds through the renderer's transform (fine for the blend-shape tools, approximate for posed characters).
- Shaders without a `_Cull` property are assumed to cull back faces; a shader that is double-sided in code (e.g. Sprites) would be flagged SEE-THROUGH from behind.
- Scene copies run their ExecuteAlways Awake/OnEnable once before their MonoBehaviours are disabled (the project's two ExecuteAlways scripts, HouseNumber/StreetNameSign, only touch their own label). Model sheets 4 does not see a Prefab Mode stage (use Model sheets 3 for that prefab).
- URP renderer features with layer-based material overrides, if any were added, would affect the preview renders too.
- Timing: ~14 renders per part (plus 16 per subject for the sheets and 2 per flagged part); the camera's ~60 parts ≈ 850 shots at 160 px, well under a minute; the whole café scene is thousands of renderers → minutes, cancelable.
- Unity will create `.meta` files for `Assets/Editor/Review/`, the shader and the script on first import; they need committing on the Mac.
